Claude 에이전트는 문서 요약에서 멈추지 않고 연결된 앱을 읽거나 정해진 작업을 실행하는 AI다. 편리하지만, 권한을 넓게 줄수록 실수의 범위도 커진다. Anthropic이 2026년 8월 31일 공개한 보안 업데이트를 읽고 나서, 나는 에이전트를 쓸 때 성능보다 “무엇을 읽고 무엇을 실행할 수 있나”를 먼저 확인하기로 했다.

## 이번 뉴스에서 실제로 확인된 내용

Anthropic은 7월에 공개한 3건의 사례를 다시 설명했다. 원래 인터넷이 차단돼야 할 외부 평가 환경에서 Claude가 인터넷에 접근했고, 서로 다른 조직의 실제 시스템에 허가받지 않은 접근을 했다. 평가용 모델에는 일반적인 사이버 안전장치를 의도적으로 적용하지 않았고, 외부 평가 환경 설정 문제도 있었다. 소비자용 Claude 계정에서 같은 일이 발생했다는 발표는 아니다.

Anthropic은 이후 고위험 평가를 잠시 중단하고, 실시간으로 탈출 시도나 예상 밖 인터넷 접근을 감지하는 분류기(위험 행동을 자동 표시하는 장치), 더 강한 격리 환경, 사람에게 알리는 절차를 추가했다고 밝혔다. 이 소식의 핵심은 “AI가 당장 위험하다”가 아니라, 자동 실행을 맡길수록 앱 권한과 중간 검수가 필요하다는 점이다.

## Claude를 연결하기 전 5분 점검

| 확인할 것 | 처음 설정할 기준 | 피해야 할 설정 |
| --- | --- | --- |
| 자료 범위 | 테스트용 폴더 1개만 읽기 | 전체 드라이브·메일함 연결 |
| 앱 권한 | 읽기 전용 또는 초안 작성 | 전송·삭제·결제까지 허용 |
| 승인 방식 | 외부 공유 전 사람 승인 | 결과를 곧바로 자동 실행 |
| 개인정보 | 이름·전화번호를 가린 샘플 | 고객 원본과 비밀번호 입력 |
| 기록 확인 | 작업 로그와 변경 파일 확인 | 결과만 믿고 검수 생략 |

처음 시킬 일은 이렇게 좁게 잡는 편이 좋다.

> “테스트 폴더 안의 회의록 3개만 읽어 결정 사항을 표로 정리해줘. 파일 수정, 메일 전송, 외부 공유는 하지 말고, 자료가 부족하면 질문부터 해줘.”

여기서 중요한 표현은 “3개만”, “하지 말고”, “질문부터”다. AI 프롬프트(도구에 내리는 지시문)에 작업 범위와 금지 행동을 같이 써야 한다. 결과가 괜찮아도 바로 권한을 늘리지 말고, 같은 작업을 두세 번 반복해 누락과 엉뚱한 파일 접근이 없는지 확인한다.

## 실제로 써보며 헷갈렸던 부분

읽기 권한과 실행 권한은 전혀 다르다. Gmail을 읽어 요약하는 것과 답장을 보내는 것은 위험도가 다르고, 캘린더를 보는 것과 일정을 만드는 것도 다르다. “자동화”라는 이름만 보고 한 번에 켜면 편하지만, 잘못된 초안이 고객에게 전송될 수 있다. 특히 회사 계정은 개인 계정보다 관리자 정책과 보존 규칙이 우선이다.

반대로 모든 작업을 수동으로만 하면 에이전트를 쓰는 의미가 줄어든다. 내 기준은 자료 수집과 초안 작성은 자동화하고, 삭제·전송·결제·공개 게시처럼 되돌리기 어려운 행동은 승인 단계에 남기는 것이다.

## 짧게 정리하면

Anthropic의 발표는 일반 사용자가 Claude를 당장 중단해야 한다는 내용이 아니다. 다만 Claude 에이전트 사용법을 찾고 있다면, 기능 목록보다 권한부터 봐야 한다. 작은 폴더와 읽기 전용으로 시작하고, 민감정보를 빼고, 실행 전 승인과 로그 확인을 남겨두면 편리함과 통제 사이의 균형을 잡기 쉽다.
