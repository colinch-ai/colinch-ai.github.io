고객 인터뷰가 쌓인 PM·UX 담당자라면 ChatGPT·Claude·Gemini 무료 플랜으로 첫 요구사항 표를 만들 수 있다. 고객 이름·연락처·계약 조건이 든 원문은 그대로 올리지 않는다. 목표는 AI가 요구를 결정하는 것이 아니라, 녹취의 근거 문장으로 우선순위 논의를 시작하는 것이다.

## 무료로 시작할 때의 입력과 결과물

| 단계 | 넣을 자료 | 받아야 할 결과 | 사람이 확인할 것 |
|---|---|---|---|
| 1. 정리 | 비식별화한 인터뷰 1~3건 | 발언·문제·상황 표 | 발언을 임의로 합치지 않았는가 |
| 2. 묶기 | 같은 형식의 표 여러 개 | 문제군·빈도·영향도 | 빈도와 중요도를 혼동하지 않았는가 |
| 3. 결정 보조 | 제품 목표와 제약 | 요구사항 후보·확인 질문 | 실제 요구와 AI의 추론이 분리됐는가 |

핵심은 원문을 기능 목록으로 바로 바꾸지 않고 중간 표를 두는 것이다. ChatGPT 무료 플랜은 파일 업로드·데이터 분석에 별도 한도가 있고([Free Tier FAQ](https://help.openai.com/en/articles/9275245-chatgpt-free-tier-faq)), 프로젝트는 무료·유료 모두 사용할 수 있다([프로젝트 안내](https://help.openai.com/ko-kr/articles/10169521-using-projects-in-chatgpt)). Claude 무료 플랜은 사용량이 제한되고, Gemini는 프롬프트당 최대 10개 파일·파일별 100MB 조건이 있다([Claude 요금제](https://support.claude.com/en/articles/11049762-choose-a-claude-plan), [Gemini 업로드](https://support.google.com/gemini/answer/14903178?co=GENIE.Platform%3DDesktop&hl=en-GP)). 주 1~2건이면 무료로 시작하고, 긴 녹취를 반복 비교하거나 팀 공유가 필요할 때 유료를 검토한다.

## 복사해서 쓰는 요구사항 추출 프롬프트

녹취 전체를 한 번에 요약해 달라고 하지 말고, 근거와 추론을 다른 열로 고정한다.

```text
너는 PM의 인터뷰 분석 보조자다. 아래 녹취에 없는 사실을 만들지 마라.
다음 열의 Markdown 표를 만들어라.
ID | 원문 발언(짧은 인용) | 사용자의 상황 | 반복되는 문제 | 원하는 결과 | 근거 수준(직접 발언/해석/확인 필요)

규칙:
1. 화자와 고객을 이름 대신 고객 A, 고객 B로 표시한다.
2. 기능 이름을 바로 제안하지 말고 문제를 먼저 적는다.
3. 한 고객의 불만을 전체 고객의 빈도로 표현하지 않는다.
4. 불확실한 내용은 “확인 필요”로 남기고, 각 행에 확인 질문을 1개 붙인다.

[비식별화한 녹취]
```

표를 다시 넣고 “문제의 빈도·매출 영향·구현 난이도를 근거 없이 점수화하지 말라”고 지시한다. AI 우선순위는 토론용 초안이며, 최소 두 명의 원문을 사람이 대조해야 한다.

## 개인정보와 유료 전환 기준

입력 범위부터 줄인다. 이름·전화번호·이메일·회사명·주문번호를 가리고, 계약서나 미공개 가격표는 승인 없이 올리지 않는다. ChatGPT는 모델 개선 사용을 끌 수 있지만 저장된 파일이 자동 삭제되지는 않는다([데이터 제어](https://help.openai.com/en/articles/7730893-data-controls-in-chatgpt)). Gemini도 Keep Activity와 인간 검토 조건을 확인해야 한다([개인정보 허브](https://support.google.com/gemini/answer/13594961?hl=en)).

| 상황 | 선택 |
|---|---|
| 공개 인터뷰나 비식별화한 1~3건 | 무료 플랜으로 표 추출 후 수동 검수 |
| 매주 많은 파일을 비교 | 사용량·파일 한도가 넉넉한 유료 플랜 검토 |
| 고객 식별정보와 팀 공유가 필수 | 개인 플랜 결제보다 회사 보안·보존 정책 확인 |

짧게 말하면, 구매할 기준은 “더 그럴듯한 요약”이 아니라 반복 업로드 한도와 조직의 데이터 처리 조건이다. 요구사항 표의 각 행에 원문 근거와 확인 질문이 없으면 무료든 유료든 아직 검증 가능한 결과물이 아니다.
