이 그림에서 볼 것은 AI가 장애 원인을 단정하는 장면이 아니라, 흩어진 로그와 메모를 사람이 확인할 회고표로 바꾸는 흐름이다.

IT 운영자나 개발지원 담당자가 장애 뒤에 타임라인, 고객 영향, 후속 작업을 매번 다시 쓰고 있다면 ChatGPT·Claude·Gemini 무료 플랜으로 비식별화한 기록 1건부터 시험하는 선택이 유리하다. 반대로 원본 로그에 고객 식별자·토큰·비공개 인프라 정보가 있고 자동으로 티켓을 닫으려는 경우엔 개인 계정이 적용 대상이 아니다. AI는 회고 초안을 만들 뿐, 원인과 책임을 확정하는 도구가 아니다.

## 회고 결과물을 문단이 아닌 표로 고정한다

Google SRE는 비난 없는 포스트모템과 구체적인 corrective action을 강조한다. Claude도 공식 활용 예시에서 타임스탬프, 고객 영향, 근본 원인, 담당자가 있는 액션 아이템을 회고 초안의 구성으로 제시한다. 이 기준을 짧은 장애 기록에 적용하면 결과물은 아래처럼 나뉜다.

| 산출물 | AI가 할 일 | 사람이 확인할 일 |
|---|---|---|
| 타임라인 | 시각·사건·근거 로그를 순서대로 배열 | 시간대, 누락 구간, 로그 원문 |
| 고객 영향 | 영향을 받은 기능·기간·범위 추출 | 실제 지표와 공지 내용 |
| 원인 후보 | 직접 원인과 기여 요인을 분리 | 원인 확정 여부와 재현 가능성 |
| 액션표 | 예방·탐지·대응 작업으로 분류 | 담당자, 기한, 완료 조건 |

## 복사해서 쓰는 장애 회고 프롬프트

로그와 메모에서 비밀값을 지운 뒤, 사건 ID를 `INC-001`처럼 바꿔 넣는다.

```text
너는 IT 장애 회고 편집자다. 아래 기록만 사용하고 원인이나 수치를 추측하지 마라.

출력 순서:
1. 타임라인: 시각(시간대 포함) | 사건 | 근거 원문 또는 로그 ID
2. 고객 영향: 기능 | 시작·종료 시각 | 확인된 영향 | 근거
3. 원인 후보: 직접 원인 | 기여 요인 | 아직 확인하지 못한 점
4. 액션표: 유형(예방/탐지/대응) | 구체적 작업 | 담당 역할 | 기한 | 완료 판정

담당자와 기한이 기록에 없으면 빈칸 대신 “확인 필요”라고 표시해라.
사람이나 팀을 비난하는 표현은 쓰지 말고, 사실과 해석을 분리해라.
로그:
{{비식별화한 장애 기록}}
```

“왜 장애가 났나”만 묻는 것보다 `근거 원문 또는 로그 ID`를 함께 요구하는 편이 낫다. 액션도 “모니터링 강화”처럼 쓰지 말고 “결제 API 5xx 비율이 5분 평균 2%를 넘으면 온콜 알림”처럼 완료 여부를 판정할 수 있게 바꾼다. 실제 수치와 임계값은 조직 기준으로 넣어야 한다.

## 무료와 유료의 경계

| 상황 | 시작 선택 | 유료·업무용 검토 신호 |
|---|---|---|
| 짧은 메모 1~2건 | 무료 채팅, 가명 데이터 | 해당 없음 |
| 긴 로그와 여러 파일 | 무료로 작은 구간 시험 | 업로드·문맥 한도가 반복적으로 작업을 끊음 |
| 팀 회고와 권한 관리 | 승인된 회사 환경 | 공유 범위, 보관, 감사 로그가 필요함 |
| 자동 티켓 생성 | 보류 후 별도 설계 | 실행 권한과 실패 시 되돌리기가 준비됨 |

무료 계정으로는 공개 샘플이나 가상 로그 3건을 처리하고 `타임라인 누락 수·원인 추정 수·사람이 고친 액션 수`를 기록한다. 이 수치가 줄지 않는데 유료 결제를 하면 처리량만 늘고 회고 품질은 그대로일 수 있다. 업무용 계정은 플랜 이름보다 조직의 보관·삭제·접근권한 정책이 맞는지가 기준이다.

개인용 ChatGPT는 데이터 제어에서 모델 개선 사용을 끌 수 있고, 임시 채팅은 모델 개선에 사용되지 않지만 안전 목적의 보관 가능성이 있다. Anthropic은 상업용 제품의 입력·출력을 기본적으로 모델 학습에 사용하지 않는다고 안내한다. Gemini도 프롬프트와 업로드 파일이 처리 대상이라고 설명하므로, 세 서비스 모두 회사 정책을 대신하지는 않는다. 확인 날짜는 2026년 10월 15일이며 계정·지역·워크스페이스 조건은 바뀔 수 있다.

## 회고 전 검수 체크리스트

- [ ] API 키, 토큰, IP, 고객 ID, 내부 URL을 지웠다.
- [ ] 모든 시각에 시간대가 붙어 있다.
- [ ] 고객 영향은 추정치와 확인된 수치를 구분했다.
- [ ] 원인 후보마다 로그 ID나 근거 문장이 있다.
- [ ] 액션마다 담당 역할과 완료 조건이 있다.
- [ ] AI가 만든 원인·책임 판단을 승인 문서로 바로 사용하지 않았다.

장애 회고에서 AI의 값어치는 그럴듯한 사과문이 아니라, 다시 열어볼 근거와 실행할 작업을 같은 형식으로 남기는 데 있다. 짧은 비식별 기록은 무료로 검증하고, 한도보다 팀 권한과 보관 정책이 병목일 때만 유료 또는 업무용 환경을 비교하면 된다.
