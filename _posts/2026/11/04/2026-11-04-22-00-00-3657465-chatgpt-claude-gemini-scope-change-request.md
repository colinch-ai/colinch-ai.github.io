이 그림에서 볼 부분은 AI가 가격을 정하는 장면이 아니라, 원래 약속과 새 요청의 차이를 표로 남기는 흐름이다.

프리랜서나 소규모 에이전시가 메신저로 들어오는 “이것도 같이 해주세요”를 매주 받는다면 ChatGPT·Claude·Gemini 무료 플랜으로 **변경요청서 초안, 영향 범위, 확인 질문**을 만드는 선택이 유리하다. 반대로 계약서 원문과 고객 개인정보를 개인 계정에 그대로 넣거나, AI가 추가 금액을 확정해 바로 보내게 하려는 경우에는 이 방법이 맞지 않다.

## 범위 밖 요청을 표로 바꾸는 기준

공공 PMO 양식과 Microsoft의 프로젝트 변경 관리 안내는 변경 요청에 요청 내용, 사유, 일정·비용·범위 영향, 승인 상태를 남기는 구조를 공통으로 둔다. 이 항목을 고정하면 “기분상 일이 늘었다”가 아니라 상대와 확인할 질문이 된다.

| 입력 | AI가 만들 초안 | 사람이 확인할 것 |
|---|---|---|
| 기존 작업 범위 | 약속된 산출물·제외 항목 | 견적서·계약서 원문 |
| 새 메시지 | 추가 요청 한 문장 | 실제로 새 일인지 |
| 영향 | 일정·작업량·의존 작업 | 시간과 단가 계산 |
| 미확인 정보 | 질문 3~5개 | 고객에게 보낼 표현 |

## 복사해서 쓰는 프롬프트

고객명, 연락처, 계약번호, 실제 금액은 `고객 A`, `프로젝트 X`, `금액 미기재`처럼 바꾼 뒤 넣는다.

```text
너는 프리랜서 프로젝트의 변경요청 정리 보조자다.
아래 [기존 범위]와 [새 요청]만 근거로 표를 만들어라.
열: 요청 ID | 기존 범위와의 관계 | 추가 작업 | 일정 영향 | 비용 산정에 필요한 정보 | 확인 질문 | 근거 문장
원문에 없는 시간·단가·승인 여부는 추정하지 말고 '미확인'으로 써라.
추가 요청을 거절하거나 가격을 확정하지 말고, 사람이 확인할 질문을 최대 5개로 제시하라.
```

결과에서 `추가 작업`과 `근거 문장`이 실제 메시지에 연결되는지 확인한다. “랜딩 페이지 수정”처럼 뭉뚱그려졌다면 화면 수, 수정 횟수, 기획·개발 포함 여부를 질문으로 다시 쪼갠다. 가격은 `추가 예상 시간 × 내 단가 + 외부 비용`처럼 계산 가정을 따로 적고, AI가 만든 숫자를 견적 확정값으로 복사하지 않는다.

## 무료와 유료의 경계

| 상황 | 선택 | 이유 |
|---|---|---|
| 요청 1~3건, 짧은 메시지 | 무료 플랜 | 표 구조와 질문 품질을 시험하기 충분하다 |
| 프로젝트 자료를 반복 참조 | ChatGPT Projects·Claude Projects·Gemini 파일 분석 | 파일 수·사용량·문맥 한도가 병목이 되는지 확인한다 |
| 여러 고객 자료, 팀 승인·보관 필요 | 회사 승인 업무용 환경 | 개인 유료 계정만으로 권한·감사 문제가 해결되지 않는다 |

확인 날짜는 2026년 11월 4일이다. OpenAI 공식 안내상 ChatGPT Projects는 Free가 프로젝트당 5개 파일, Plus·Go는 25개, 일부 상위 플랜은 40개까지 지원한다. Gemini는 한 프롬프트에 최대 10개 파일을 안내하지만 사용량 제한이 있고, Claude Projects도 무료 계정은 프로젝트 5개 제한이 있다. 한도와 플랜은 바뀔 수 있으므로 결제 전 공식 안내를 다시 확인한다.

체크리스트는 짧게 끝낸다.

- [ ] 계약·견적서의 원래 범위를 사람이 확인했나
- [ ] 고객 개인정보와 비밀 금액을 비식별화했나
- [ ] 모든 추가 판단에 원문 근거가 붙었나
- [ ] 일정·단가·승인 상태가 `미확인`과 분리됐나
- [ ] 고객에게 보내기 전 사람이 문장을 승인했나

AI의 역할은 무료든 유료든 “얼마를 청구할지” 결정하는 데 있지 않다. 범위 차이와 빠진 질문을 같은 형식으로 남겨 협상 가능한 변경요청으로 바꾸는 데 있다. 일주일에 몇 건 처리하는지, 사람이 고친 행이 몇 개인지 기록한 뒤 실제 한도와 검수 시간이 병목일 때만 유료 전환을 검토하면 된다.
