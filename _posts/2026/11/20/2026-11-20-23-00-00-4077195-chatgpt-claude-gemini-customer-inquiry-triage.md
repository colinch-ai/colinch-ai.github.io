이 그림에서 볼 것은 AI가 문의에 답하는 장면이 아니라, 분류 결과와 답변 초안을 사람이 승인하는 흐름이다.

하루에 비슷한 고객 문의를 10건 이상 처리하는 상담 담당자라면 ChatGPT·Claude·Gemini 중 무료 대화창 하나로 **문의 유형, 긴급도, 담당자, 답변 초안**을 표로 만들 수 있다. 문의량이 적거나 모든 답변이 법무·환불 승인을 거쳐야 한다면 유료 구독보다 기존 FAQ와 수동 검수가 낫다. AI에게 발송 권한까지 주는 방식은 이 글의 범위가 아니다.

## “요약해줘”가 부족한 이유

고객 문의를 그대로 요약하면 중요한 분기 기준이 사라진다. “배송이 늦다”는 배송조회 안내일 수도 있고, 분실 신고일 수도 있다. AI가 모호한 문장을 임의로 확정하지 않도록 `판정 근거`와 `사람이 확인할 질문`을 함께 요구해야 한다.

| 결과 열 | 쓰임 | 사람이 확인할 것 |
|---|---|---|
| 문의 유형 | 결제·배송·계정·기술 오류 등 | 회사 기준표에 맞는가 |
| 긴급도 | P0~P2 또는 낮음·보통·높음 | 업무 중단·환불 기한이 실제로 있는가 |
| 담당자 | CS·개발·정산 등 | 권한과 실제 담당 팀이 맞는가 |
| 답변 초안 | FAQ에 근거한 1차 답변 | 약속, 금액, 기한을 새로 만들지 않았는가 |
| 보류 사유 | 정보 부족·승인 필요 | 고객에게 되물을 질문이 분명한가 |

## 무료로 시작할 조건과 유료로 넘어갈 조건

처음에는 개인정보를 지운 문의 5~10건을 한 번에 붙여 넣고 결과표를 만든다. 세 서비스의 차이를 추상적인 “똑똑함”보다 같은 기준표를 지키는지로 비교하는 방식이다.

| 상황 | 무료 대화창 | 유료·팀 환경 검토 |
|---|---|---|
| 하루 문의가 적고 1명이 처리 | 적합. 템플릿을 메모장에 저장 | 구매하지 않아도 됨 |
| 매일 같은 FAQ와 기준표 사용 | 가능하지만 복사 작업이 남음 | 프로젝트·지식 저장 기능 비교 |
| 여러 명이 같은 답변을 검토 | 결과 공유가 번거로움 | 권한, 로그, 보안 정책 확인 |
| 원문에 고객 식별정보 포함 | 개인 무료 계정에 바로 업로드 금지 | 회사 승인 환경 또는 비식별화 필요 |

ChatGPT 프로젝트는 무료에서도 사용할 수 있지만 파일 수와 사용량은 요금제에 따라 달라진다. [OpenAI 공식 문서](https://help.openai.com/en/articles/10169521-projects)는 무료 프로젝트의 파일 수를 5개로 안내하고, 개인 요금제에서는 데이터 제어 설정이 적용된다고 설명한다. Claude의 프로젝트는 공식 도움말 기준으로 유료 플랜 기능이다. Gemini도 [공식 제한 안내](https://support.google.com/gemini/answer/16275805?hl=en)에 따라 사용량과 기능이 요금제·수요에 따라 달라질 수 있다. 숫자는 바뀔 수 있으므로 결제 전 화면의 현재 제한을 확인해야 한다.

## 복사해서 쓰는 분류 프롬프트

아래 프롬프트는 답변 생성보다 분류와 보류 판정을 앞세운다. `회사 기준표` 부분만 실제 규칙으로 바꾼다.

```text
너는 고객지원 보조다. 아래 문의를 회사 기준표에 따라 분류하되, 원문에 없는 사실은 만들지 마라.

회사 기준표:
- 유형: 결제 / 배송 / 계정 / 기술 오류 / 기타
- P0: 여러 고객의 이용이 막혔거나 보안 사고 가능성이 있음
- P1: 한 고객의 핵심 기능이 막혔고 우회 방법이 없음
- P2: 일반 질문, 사용법, 단순 요청

각 문의마다 다음 표를 반환해라.
번호 | 유형 | 우선순위 | 판정 근거(원문 인용) | 담당 팀 | 답변 초안 | 보류 사유 | 확인 질문

규칙:
1. 원문에 없는 주문번호·환불일·복구 예정일을 쓰지 마라.
2. 근거가 부족하면 우선순위를 '판정 보류'로 표시해라.
3. 답변 초안은 FAQ에 있는 사실만 사용하고, 모르면 담당자 확인으로 끝내라.
4. 고객 이름, 이메일, 전화번호, 주소는 결과에 다시 출력하지 마라.

[회사 FAQ와 기준표]
[개인정보를 지운 고객 문의 목록]
```

## 10건만 검수해도 구독 판단이 선명해진다

결과를 바로 발송하지 말고 아래 체크리스트로 표시한다.

- [ ] 유형과 우선순위마다 원문 근거가 있는가
- [ ] P0·P1로 분류된 건을 사람이 다시 읽었는가
- [ ] 답변에 없는 금액·날짜·정책이 들어가지 않았는가
- [ ] 기준표에 없는 문의가 보류로 빠졌는가
- [ ] 개인정보를 입력 전 제거했고 결과에도 남지 않았는가
- [ ] 10건 중 수정이 필요한 행을 별도로 기록했는가

가상의 10건 점검이라도 사람이 3건 이상 고쳐야 한다면 프롬프트보다 기준표와 FAQ가 부족한 상태다. 반대로 반복 문의가 같은 형식으로 쌓이고 수정 행이 1~2건으로 줄면 프로젝트에 기준표를 저장하는 유료 전환을 검토할 수 있다. 이는 성능 보장이 아니라 팀의 복사·공유 비용을 줄일지 판단하는 기준이다.

짧게 정리하면, 무료 AI는 비식별 문의를 표로 바꾸는 시험에 충분하다. 유료 플랜은 더 좋은 답변이라는 이유보다 반복 입력, 공유 권한, 프로젝트 파일, 사용량 제한이 실제 병목일 때 선택한다. 최종 분류와 고객 발송은 반드시 사람이 맡긴다.
